# 山谷守卫 · Tank Battle

一款在网页里运行的几何风格 3D 坦克守卫战。穿过山林、炸开岩壁、收集补给，选择经典攻防或五波防守，与朋友一起守住这片山谷。

**[直接游玩](https://zhaoyunxiong.github.io/TankBattle/)**

支持电脑键鼠与手机触控，横屏、竖屏分别适配。所有模型由代码生成，音效由 Web Audio 合成，无需外部素材。

## 游戏模式

开始界面默认选中 **经典模式**；也可切换为 **防守模式**，然后选择单人战役或创建房间。可独立选择休闲、普通（默认）、挑战难度，并记住上次选择。两种模式都支持 1～4 人，联机模式、难度与地图由房主在开房前选定，队友在大厅查看本局规则。

| 模式 | 阵地与敌军 | 胜利条件 |
| --- | --- | --- |
| 经典模式（默认） | 非对称双方营地，敌方围墙可摧毁，敌军有驻守部队和分批出击的有限增援 | 保住己方营地并摧毁敌军营地 |
| 防守模式 | 己方营地承受五波逐渐增强的攻势，波间休整与修复 | 击退全部五波敌军 |

这里的经典模式按双方阵地攻防设计，保留当前 3D 视角、血量和炮击冷却，并非逐项复刻某个红白机版本。两种模式中，己方营地被毁或小队所有备用坦克耗尽都会失败。

## 难度与攻防节奏

| 单人规则 | 休闲 | 普通（默认） | 挑战 |
| --- | --- | --- | --- |
| 同时在场敌军上限 | 2 | 3 | 4 |
| 经典模式进攻 / 驻守 | 1 / 1 | 2 / 1 | 3 / 1 |
| 经典模式敌军总数（含驻军） | 12 | 18 | 24 |
| 经典模式敌营血量 | 280 | 360 | 480 |
| 清空进攻部队后的增援间隔 | 25 秒 | 20 秒 | 12 秒 |
| 防守模式五波数量 | 3～7 | 4～8 | 5～9 |
| 防守模式波间休整 | 18 秒 | 15 秒 | 12 秒 |

上表为小型地图；中、大地图的经典反攻窗口分别增加 10 / 20 秒，防守波间休整增加 5 / 10 秒，敌军数量不随地图面积增长。

经典模式无需清掉驻军就能触发反攻窗口；窗口内不会补兵，可以维修、推进或进攻敌营。增援耗尽后，仍需摧毁敌营核心才能获胜。防守模式休整时保留营地与存活围墙的修复。

普通敌军的快速 / 普通 / 重型坦克血量分别为 80 / 100 / 140，普通与快速敌军装填 3.5 秒，重型装填 3 秒；玩家初始装备为 120 血、标准炮 20 伤害、1 秒装填；工厂升级提供温和加成。受损导致的减速最多 15%，仍会冒烟和增加散布。

敌军需要看见玩家才能追踪，失去视线后只搜索最后目击的位置。普通难度发现目标后有 0.8～1.2 秒反应时间，炮口提前约 0.4 秒闪光并锁定这次射击方向；同一玩家最多被 2 辆敌军主动集火。小队每击毁 3 辆敌军，会在击杀者附近的可达位置保证一个维修包，满血时可留给之后使用。

合作模式增加敌军总数与同时在场数量，不额外提高单辆敌军血量、命中精度或反应速度。难度由房主统一模拟，队友大厅和暂停页均显示本局难度。

## 玩法

- 按镜头方向自由移动，车身自动转向，支持斜向行驶；炮塔独立瞄准。
- 第三人称跟随镜头，默认抬高、拉远以看清战场，可自由旋转、俯仰和缩放；准星显示实际射击方向。
- 坦克和营地均有血量，普通炮弹不会秒杀满血坦克；开火需要装填。
- 自己的血量以坦克上方小血条显示，受损时显示减速提示；备用坦克数与得分放在暂停页。
- 左上仅保留暂停与己方营地血条，右上小地图使用透明底；敌营血条跟随阵地，模式、难度与敌军计数收进暂停页。
- 加速模式提升 60% 移速，左侧蓝条代表耐力，满耐力可持续移动约 8 秒；停止加速 1 秒后每秒恢复 15 点。原地停留、撞墙不扣耐力，耗尽后自动退出，恢复至少 20 点可再次起步；浅水和受损减速仍然生效，加速增加扬尘与涉水尾波。
- 蓄力模式按住积蓄、松开发射，1.6 秒蓄满，伤害从 20 增至 56（2.8 倍），满蓄力仍不会一炮击毁满血坦克。单发装填 1.35 秒，装填升级与快速装填仍生效；蓄力炮保留连发补给次数。带发光炮弹、尾迹、强烈镜头震动与车身后座力，满蓄力向炮口反方向退约 1.2 米，遵守障碍和深水边界。蓄满可继续保持，暂停、展开地图、失焦、触控取消和断线都会取消当前蓄力。
- 受损后冒烟、减速、精度下降，维修后恢复。
- 长效补给：快速装填按小 / 中 / 大地图持续 60 / 90 / 120 秒；三连发提供 24 次主动开炮；强化装甲吸收 90 点伤害；回血恢复 35%。同类可补充，上限为两份，连发和护盾不随赶路消耗。
- 小、中、大三幅初始地图：薄雾山谷 96×120、白桦河湾 144×180、双桥远山 192×240；河流、道路、高地和营地布局各不相同。规模与难度独立选择。
- 中央谷道、最高约 12 米的侧翼台地与宽缓坡均可驾驶；车身随坡面倾斜，上坡略慢，小地图用颜色区分高地。
- 炮弹具有真实高度，山坡可以挡炮，高处射击可越过低矮掩体；炮管自动辅助仰角，准星显示预计落点，相机避开坡面。
- 摧毁树木和岩壁打通捷径，敌军也会利用新路、攻击围墙；己方营地始终标记；敌营需要坦克进入 28 米侦察范围并看见营地，发现后全队立即开全图，小地图持续标记位置；敌营血量只在阵地上方显示；防守模式开局全图可见，自由相机不能提前侦察敌营。
- 松林、阔叶林、白桦林与少量枯树成片分布，树木的高度、树冠和六档色系有差异；林缘、道路和第一片高草入口预留通行空间。岩石有低石、巨石与层叠岩壁，高草与装饰矮草外形不同。
- 完全进入高草即可隐蔽；每次开炮暴露 5 秒，反复进出草丛不会重置。双方都遵守高草隐蔽。草丛外的敌军不再按距离隐藏，模型与小地图全局可见；隐蔽不挡炮，盲射仍可命中。
- 浅河可涉水，速度为正常的 60%；深河必须从桥梁通过，关键桥梁不可摧毁。弯曲岸线、水深色带、流动水纹、岸边泡沫、桥边涡流和涉水尾波帮助辨认水域。AI 遵守相同通行规则，补给只在可达位置生成。
- 普通、快速、重型三类敌人；两辆备用坦克及复活保护。防守模式保留原来的五波攻势。
- 树木与高草随风摆动、营旗飘动、云影掠过；行驶时车轮转动、车身平滑贴合坡面并留下短暂履带印，平地行驶不再强制左右晃动，扬尘与涉水飞溅随地面变化。
- 树木倒伏时保留原树种的立体树干、树冠、枝条与阴影，沿固定方向倒下并贴合坡面，留下可碾过的树桩和倒木；岩石、围墙的临时碎片淡出。坦克被毁有更强的短促震动、闪光、烟尘和扩散冲击波，在泥土地面留下几何弹坑，桥面和岩地留下焦痕；普通落地炮弹留下小弹痕。痕迹整局保留，重新开局重置，重新连接会从战场快照恢复。弹坑是视觉凹陷，不改变碰撞、移速或桥梁通行。省电模式简化远景、限制粒子和履带印数量，高草合并绘制。
- 可展开的战术地图、每人一个持续 12 秒的小队路线标记、来弹与受击方向提示、营地受袭提示，以及即将耗尽的强化提示。震动可选关闭 / 轻度 / 标准 / 强烈，流水、履带和材质破坏使用合成音效。

浅水与倒木提供战术掩护：车身深入浅水后减伤 **20%**，移动速度仍为 60%；树木倒稳后，位于树干与树冠实际范围内减伤 **25%**。多棵倒木或水域重叠只取最高一项，桥面、岸边擦水和弹坑没有减伤。先计算环境减伤，再由护盾吸收剩余伤害；双方坦克适用同一规则。血条旁显示掩护状态，离开即解除；倒木不会让坦克隐形，高草继续负责隐蔽。

绿色箱子是维修包：**满血时不会消耗，受伤后驶近即可回血**，也可留给受伤的队友。其他增益箱在满血时同样可拾取。靠近箱子会显示名称、效果和满血提示，拾取后会显示具体补给名称；地面补给按地图保留 120 / 180 / 240 秒；主要道路预放少量补给，随机补给优先落在存活玩家附近。

## 战绩、档案与工厂

每局结束后显示个人贡献排名，击毁、助攻、阵地防守、攻击敌营和团队胜利均有得分。同分并列；失败按实际贡献给予收益。战绩存储只在结算时发生，使用唯一对局 ID 防止刷新或重新连接重复领取。

- **累计荣誉**：按当局得分和难度累计，不因升级消费减少，用于军衔与生涯记录。
- **工厂金币**：荣誉收益的 15%（向下取整），胜利额外奖励 80；用于五项升级。
- **本机通关榜**：按模式、难度、地图、人数及整队装备配置分组，同分时用时较短者优先；保留最近 200 场记录，累计荣誉、金币和已结算标记继续保留。

大厅底部的“工厂与档案”可查看战绩、升级、导出或导入 JSON 存档。浏览器本地保存跨局进度；清理网站数据、无痕浏览或换设备不会自动保留同一份档案，应先导出备份。写入失败会提示导出，读取损坏时优先恢复上一份有效本机备份。当前没有账号云同步或全球排行榜，档案可由本机用户修改；未来正式联网排名应由服务器核验对局。

| 工厂项目 | 每级效果 |
| --- | --- |
| 坦克装甲 | 最大耐久 +8% |
| 履带传动 | 移速 +4% |
| 装填机构 | 装填时间 -4% |
| 阵地加固 | 营地最大耐久 +8% |
| 维修工坊 | 营地脱战 10 秒后，每 30 秒修复 10 点耐久 |

每项最多三级，费用为 150 / 300 / 500 金币；可全额退款重置。升级在下一局出发生效，初始装备仍可通过普通战役。坦克升级各自生效，阵地两项按小队成员中的各项最高等级生效一次，在大厅展示，不按人数叠加。

## 地图与后续扩展

本次提供三幅可选择的战场，尚未编排连续闯关战役。`src/game/maps.ts` 集中描述营地、出生点、山体、河流、桥梁、高草和道路；素材样式与战斗规则由所有地图共用。后续编排关卡时可以复用这些定义，调整布局、种子和敌军节奏，无需逐关重做模型或交互。

地图生成会保留道路、桥头与出生区；导航缓存随障碍被毁重建，深水与桥梁按坦克宽度检测，房主与客机共用同一套地形采样。单元测试检查三种规模、多种种子和双方可达路线；浏览器回归覆盖地图切换、高草开炮暴露、手机多指与大地图 WebRTC 同步。

## 操作

| 功能 | 电脑 | 手机 |
| --- | --- | --- |
| 移动 | WASD / 方向键，支持组合斜向移动 | 左摇杆推向哪里就往哪里走，轻推慢行 |
| 瞄准 | 单击战场锁定鼠标，鼠标移动或拖动 | 右侧拖动 |
| 开火 | 按住左键或空格 | 按住开火按钮，也能同时拖动瞄准 |
| 加速模式 | B 或加速按钮切换 | 点击加速按钮切换 |
| 蓄力模式 | Q 或蓄力按钮切换，按住左键 / 空格蓄力，松开发射 | 切换蓄力后按住开火按钮，松开发射 |
| 镜头 | 滚轮缩放、C 归位、Alt 自由观察 | ＋/− 缩放，相机按钮切换自由观察 |
| 暂停 | Esc 或左上按钮 | 左上暂停按钮 |
| 战术地图 | M 展开 / 收起，点击地图标记 | 点击小地图展开，再点目标位置标记 |

移动方向以当前镜头为准，按左就向画面左侧移动，车身自动转向，无需再按前进。旋转镜头后方向随之调整；移动不改变炮塔瞄准方向。镜头默认距离 18、俯仰约 40°，缩放范围 8～30；C 恢复默认高度和距离并朝向车头。

手机页面拦截双指捏合和双击放大，镜头远近通过游戏内的 ＋/− 按钮调整。单指瞄准保持由最先按下的手指控制，额外手指不会抢走镜头；左摇杆与右侧开火仍可同时操作。菜单和操作手册保留单指滑动。

## 手机联机

2～4 人合作。房主在手机网页中创建房间，其他人用六位房间号、二维码或邀请链接加入，准备完成后由房主开始战役。不需要电脑或安装服务器程序。

房主统一模拟敌军、命中、血量、补给与地图破坏，其他玩家提交输入并接收完整战场快照。每位玩家独立控制镜头，默认关闭队友和本方营地围墙的友军伤害；经典模式中可以摧毁敌军围墙与核心。

战场快照使用支持分片的二进制传输，适应扩大后的地图和炮弹高度数据。更新游戏后，所有玩家都应刷新页面再建房，避免不同版本加入同一局。

### 网络与当前限制

- GitHub Pages 提供静态网页；多人配对使用 [PeerJS 公共服务](https://peerjs.com/server/cloud)，战场通过 WebRTC 同步。单人模式不依赖配对服务。
- 开房和加入需要能访问公共配对服务。同一允许设备互访的 Wi-Fi 更适合直连。
- **默认配置只有 STUN，没有部署可靠的公网 TURN 中继。不同运营商、移动数据、严格 NAT 或隔离网络可能无法直连。** 稳定跨网联机需要额外配置 TURN，GitHub Pages 本身无法提供中继。
- 房主切到后台时主动暂停战场；失去连接时队友显示等待提示。没有自动更换房主，房主离开会结束本局。
- 开战后只允许同一页面会话重连已有坦克，不支持新玩家中途加入。
- 尚未实现完全断网的游戏缓存与手动配对。
- 手机以新版 Android Chrome、iPhone Safari 为兼容目标。移动视口和多点触控自动化验证不等同于实体手机测试，内置浏览器的能力也可能不同。

## 开发与验证

使用 Node.js 24：

    npm ci
    npm run dev

打开 http://localhost:5173/TankBattle/ 。通过手机访问局域网 HTTP 调试地址时，部分安全上下文功能可能受限；完整功能请使用 HTTPS 站点。

    npm test
    npm run build
    npm run test:e2e

单元测试覆盖两种模式的胜负、驻军与增援、双方围墙伤害、大地图导航、补给提示，以及三档难度、有限增援与休整、视线遮挡、开炮预警、集火限制、保底维修、冷却、受损、回血、复活、输入边界、方向移动和斜向限速。浏览器测试覆盖桌面方向移动/开火/暂停、手机横竖屏、多指操作，以及两个独立会话的真实 WebRTC 战场同步。

Windows 测试使用本机 Edge；其他平台先执行 npx playwright install chromium。完整联机测试会访问公共配对服务。CI 运行无需外部配对服务的桌面、横竖屏、工厂和持久痕迹浏览器测试，截图保存在 Actions 工件中。

可安装 Playwright WebKit，并设置 TANK_TEST_BROWSER=webkit，单独运行名称含“WebKit 手机”的测试。发布后运行 node scripts/check-published.mjs，检查公开页面的单人流程、手机布局与实际双会话联机。

## 部署

推送 main 后，GitHub Actions 自动测试、构建并发布。Settings → Pages → Source 设为 **GitHub Actions**。生产路径为 /TankBattle/，产物在 dist/；更换站点路径时同步修改 vite.config.ts。

可选构建环境变量：

| 变量 | 用途 |
| --- | --- |
| VITE_PEER_HOST | 自建 PeerServer 的 HTTPS 域名，默认使用公共服务 |
| VITE_PEER_PORT | 服务端口，默认 443 |
| VITE_PEER_PATH | 服务路径，默认 / |
| VITE_ICE_SERVERS | 自定义 RTCIceServer 数组 JSON，接入 STUN/TURN |

本地变量可放在未提交的 .env.local。VITE_ 变量会进入公开网页，不能存放长期私密凭证。生产 TURN 应由后端签发短期凭证。

## 结构

    src/game/maps.ts         三档地图配置、区域和水域规则
    src/game/visibility.ts   高草隐蔽、视线与小队侦察
    src/game/cover.ts        浅水与倒木减伤、共用倒伏几何
    src/game/factory.ts      装备等级、价格与联机校验
    src/profile.ts           版本化档案、结算去重与存储边界
    src/profile-ui.ts        工厂、战绩与存档备份界面
    src/game/balance.ts      难度参数与合作人数缩放
    src/game/simulation.ts   固定步长战斗模拟与敌军 AI
    src/game/terrain.ts      共享地形高度、坡速和坡面射线
    src/game/combat.ts       炮管仰角与三维弹道碰撞
    src/game/world.ts        可复现地图、碰撞和 A* 导航
    src/game/renderer.ts     Babylon.js 场景、坦克、光影和粒子
    src/game/audio.ts        合成音效
    src/network.ts           手机房间和战场快照同步
    src/controls.ts          键鼠、多点触控和自由镜头
    src/main.ts              大厅、设置、战场 HUD 和游戏流程
    tests/                  战斗规则与浏览器验证
